# 项目工程手册

本文件记录供 AI Agent 使用的长期有效信息，保持低频修改。动态状态与验证证据见 [项目当前状态](项目当前状态.md)。未确认项不构成实施授权。

## 一、项目定义

- 仓库标识：`hailinklabs-website`。
- 仓库地址：`https://github.com/gaozichen2012/hailinklabs-website`。
- 产品定位、服务对象和核心目标：待用户确认，不从仓库名称推断具体业务。
- 负责范围：项目业务职责待确认；AI 上下文文档负责提供工作规则、长期工程定义与动态状态。
- 不负责范围：业务非目标待确认。未经确认的产品能力、外部系统责任和部署责任不纳入已授权范围。

## 二、系统架构

- 系统组成、运行边界、部署拓扑与数据流：待确认。
- 业务模块及其单一职责、接口归属：待确认，不预设模块或重叠职责。
- 与其他仓库、服务或平台的关系：待确认；不得仅凭组织名或仓库名认定依赖关系。
- AI 上下文职责划分：根目录 `AGENTS.md` 规定执行行为；本文件定义长期工程信息；`docs/项目当前状态.md` 保存动态快照。

## 三、技术体系

- 语言、框架、依赖管理、构建、测试与部署技术：待确认。
- Git 文本规范：根目录 `.gitattributes` 设置 `* text=auto`，由 Git 自动识别文本并进行规范化处理；该设置不构成构建或运行能力的证据。

## 四、核心设计原则

- 以可核实证据为依据，明确区分已确认事实、实现状态、历史证据与待确认事项。
- 长期定义与动态状态分离，任务结果不自动改变长期设计。
- 产品和架构决定须有用户确认；不将建议方案写成既定设计。
- 后续确定模块边界时明确职责和接口所有者，避免职责重叠。

## 五、关键设计说明

- 三文件上下文结构由用户明确指定，分别承载行为规则、稳定定义和当前状态，减少任务进展对长期定义的干扰。
- 当前状态以独立问题域组织，允许多个并行工作方向共存，并通过更新前重读避免覆盖其他方向的信息。
- 产品、协议、数据模型及运行架构方面的关键设计：待确认；确认后仅记录长期有价值的结论与原因。

## 六、冻结规则

- 保持根目录 `AGENTS.md` 与 `docs/项目工程手册.md`、`docs/项目当前状态.md` 的上下文分工，不自行增加 TASK、DECISIONS、ROADMAP、ARCHIVE 等体系。
- 未经用户确认，不扩大产品范围、不修改核心架构、不改变协议语义；既有冻结规则的替代同样需要用户确认。
- 业务层面的冻结接口、协议或数据模型：待确认，不虚构冻结对象。
- 遇到代码与长期定义冲突时，记录到当前状态并请求确认，不静默改写长期规则。

## 八、AI 开发约束

- 每次任务先读两个中文文档并检查工作区；保留已有有效规则及无关修改。
- 仅在用户授权范围内修改文件；文档工作不能自行扩展为业务开发、配置变更或历史文档整理。
- 不复制大段源码、历史报告、最近提交列表或开发流水到本文件。
- 不把代码存在当作实机验证，不把历史构建结果继承到当前提交。
- 任务结束维护当前状态；长期定义仅在用户确认对应变化后更新。
