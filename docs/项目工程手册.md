# 项目工程手册

本文件记录公开网站的工程约定；实现与验证快照见 [项目当前状态](项目当前状态.md)。内部业务与运维约束由私有子模块维护。

## 一、项目定义

- 品牌：Hailink Labs，不翻译品牌名称；中文公司名称：深圳市海狸智联科技有限公司；官网英文公司展示名称：Shenzhen Hailink Technology Co., Ltd.。不附加未经证明的注册或认证描述；品牌与主体关系在网站明确显示。

- SameJob 正式产品名：Invoice Maker: SameJob；面向美国个人服务经营者的重复开票应用。未核实 App Store 正式链接前不放下载按钮或上市声明。产品按统一正式产品页面展示，不显示内部开发阶段；价格与隐私说明必须与已确认定义及实现一致。
- 联系邮箱：`gaozichen@hailinklabs.com`。

## 二、系统架构与边界

- Astro 静态站点；公开主仓库保存网站源码与公开工程说明，私有仓库 `hailinklabs-website-internal` 以 `internal/` Git 子模块挂载，保存内部资料并独立管理版本。
- GitHub Actions 不拉取私有子模块，只构建并部署主仓库 `dist/` 至 GitHub Pages。网站开发、检查和构建必须在没有 `internal/` 内容时正常运行。
- 正式源站：`https://hailinklabs.com`；`www` 跳转根域；GitHub Pages 默认域名仅作底层托管，不作公开 canonical。
- 保持既有域名与邮箱配置；相关操作必须遵守私有子模块中的完整约束。
- 不建设 CMS、数据库、后台、Contact Form、Analytics、Cookie Tracking 或运行时后端；不扩展营销与产品范围。

## 三、页面和模块职责

| 范围 | 职责 |
| --- | --- |
| `/`、`/about` | 公司介绍、品牌与法律主体关系 |
| `/products`、`/products/{product}` | 四产品目录及独立产品介绍 |
| `/products/{product}/privacy` | 各产品与源码及实际运营一致的隐私说明；保留 SameJob 原 URL |
| `/products/{product}/support`、`/contact` | 各产品支持和公司域名邮箱联系方式 |

| `src/data/site.ts`、`src/data/i18n.ts`、`src/data/zh.ts`、`src/data/products.ts` | 统一品牌、公司展示名称、联系方式、页面集合与构建期翻译 |
| `src/components/pages`、`src/pages` | 共享页面结构与中英文静态路由 |
| `src/layouts`、`src/styles` | SEO/Open Graph、导航、页脚与响应式设计 |
| `.github/workflows` | 构建验证、主分支自动部署 |

## 四、技术体系与设计原则

- Astro、TypeScript、npm lockfile；静态 HTML/CSS、系统字体、无客户端业务脚本。
- ESLint/Prettier、Astro typecheck、静态构建和 Playwright 桌面/移动视口验证。
- 统一 HTTPS canonical，内部链接和 sitemap 使用正式根域；保留无扩展名的约定 URL。
- 英文为默认版本，保留原 URL；全部业务页面在 `/zh` namespace 提供简体中文对应版本。导航使用普通链接切换到当前页面的另一语言版本；不按浏览器语言跳转，不使用 Cookie、localStorage 或客户端语言检测。
- 双语共享页面结构、Layout、组件和样式，以轻量 TypeScript 语言数据在构建时生成静态页面，不增加国际化框架或运行时后端。
- 每页使用自身 canonical；中英文对应页提供 `en`、`zh-CN`、`x-default` hreflang，默认指向英文；所有正式语言版本进入 sitemap。英文隐私政策为主要版本，中文为便于阅读的完整翻译，差异以英文为准。
- 简单、英文优先、可读、可键盘访问和响应式；不编造客户、产品能力、认证、上市状态或公司资质。
- 隐私声明必须区分本地数据、Apple iCloud/StoreKit、用户导出、客服邮件与网站托管；源码审计不代替真实后台或运营核验。

## 五、发布与资料边界

- DNS、域名与邮箱的变更必须另有明确授权，操作前读取私有子模块中的完整运维约束；只处理网站代码不需要拉取私有资料。
- 保持现有 Nameserver、网站域名绑定和邮箱服务。不得因文档迁移改变线上配置。
- 主仓库保持 Public，内部资料仓库保持 Private。两边均不得提交密码、令牌、私钥、登录状态或原始私密证据。
- 主仓库只记录子模块地址、目录和提交编号；只公开网站所需源码、公开内容和必要工程说明。内部业务与运维资料不得复制到公开源码、构建产物、提交说明、日志、Issue 或 PR。
- `main` 推送自动执行安装、lint、typecheck、发布检查、build 和浏览器测试；仅通过检查的 `dist/` 可发布。
- 先提交并推送私有子模块，再提交并推送主仓库的引用；不得引用尚未推送的私有提交。
- 隐私发布决定保留在公开的 `src/data/privacy-review.json`，详细依据放入私有资料。保持发布检查，不以迁移为由削弱审核。
- 工程检查与实际业务验收分别确认，不以网站检查替代其他验收。

## 六、AI 上下文与变更边界

- `AGENTS.md` 管执行；本文件管长期规则；项目当前状态管动态阶段、验证与风险，不创建额外任务管理体系。
- 执行前读取两个中文文档并检查 Git 分支、HEAD、工作区；保留其他工作成果，避免覆盖并行修改。
- 源码、配置、有效文档、Git 历史或用户明确确认才支持事实；未验证事项要明确标注。
- 功能修复及验证只更新当前状态；只有经用户确认的产品、架构、职责、协议或长期原则变化才更新本手册。
- 提交前检查差异并运行 `git diff --check`，只暂存已授权范围。构建、测试、实机、生产验证分层记录。
