# 项目工程手册

本文件记录公开网站的工程约定；实现与验证快照见 [项目当前状态](项目当前状态.md)。内部业务与运维约束由私有子模块维护。

## 二、系统架构与边界

- Astro 静态站点；公开主仓库保存网站源码与公开工程说明，私有仓库 `hailinklabs-website-internal` 以 `internal/` Git 子模块挂载，保存内部资料并独立管理版本。
- 网站开发、检查和构建必须在没有 `internal/` 内容时正常运行。GitHub Pages 保留现有托管；Git 上传与网站发布分开记录，推送不等于生产上线。
- 正式源站：`https://hailinklabs.com`；`www` 跳转根域；GitHub Pages 默认域名仅作底层托管，不作公开 canonical。
- 保持既有域名与邮箱配置；相关操作必须遵守私有子模块中的完整约束。
- 不建设 CMS、数据库、后台、Contact Form、Analytics、Cookie Tracking 或运行时后端；不扩展营销与产品范围。

## 四、技术体系与设计原则

- Astro、TypeScript、npm lockfile；静态 HTML/CSS、系统字体、无客户端业务脚本。
- ESLint/Prettier、Astro typecheck、静态构建和 Playwright 桌面/移动视口验证。
- 统一 HTTPS canonical，内部链接和 sitemap 使用正式根域；保留无扩展名的约定 URL。
- 英文为默认版本，保留原 URL；全部业务页面在 `/zh` namespace 提供简体中文对应版本。导航使用普通链接切换到当前页面的另一语言版本；不按浏览器语言跳转，不使用 Cookie、localStorage 或客户端语言检测。
- 双语共享页面结构、Layout、组件和样式，以轻量 TypeScript 语言数据在构建时生成静态页面，不增加国际化框架或运行时后端。
- 每页使用自身 canonical；中英文对应页提供 `en`、`zh-CN`、`x-default` hreflang，默认指向英文；所有正式语言版本进入 sitemap。英文隐私政策为主要版本，中文为便于阅读的完整翻译，差异以英文为准。
- 简单、英文优先、可读、可键盘访问和响应式；不编造客户、产品能力、认证、上市状态或公司资质。
- 隐私声明必须区分本地数据、Apple iCloud/StoreKit、用户导出、客服邮件与网站托管；源码审计不代替真实后台或运营核验。

## 五、发布与资料边界

- DNS、域名与邮箱的变更必须另有明确授权，操作前读取私有子模块中的完整运维约束；只处理网站代码不需要拉取私有资料。
- 保持现有 Nameserver、网站域名绑定和邮箱服务。不得因文档迁移改变线上配置。
- 主仓库保持 Public，内部资料仓库保持 Private。两边均不得提交密码、令牌、私钥、登录状态或原始私密证据。
- 主仓库只记录子模块地址、目录和提交编号；只公开网站所需源码、公开内容和必要工程说明。内部业务与运维资料不得复制到公开源码、构建产物、提交说明、日志、Issue 或 PR。
- 2026-10-07 用户明确要求：禁止使用 GitHub Actions，以及 GitHub 相关 AI 功能（含 Copilot 编码代理、自动 AI 审查、GitHub Models 和 AI 驱动工作流）。AI Agent 不得调用、触发、重跑、轮询 Actions 或将测试/审查委托给这些功能，也不得自行重新启用。仓库 Actions 必须保持禁用；历史工作流文件与历史证据仅留作记录。
- lint、typecheck、发布检查、build、SEO 与必要的浏览器测试均在本地执行；仅通过检查的 `dist/` 可进入另行授权的发布流程。本地 Codex 协作及既有静态搜索发现文件不属于 GitHub AI 功能。普通 Git 提交/推送可继续，提交使用 `[skip ci]` 作为额外防护；不因禁止 Actions 放松本地检查。
- 当前自动 Pages 发布已停用。新的 Git 提交不得报告为线上已更新；发布方式需要另行确认，未经授权不切换托管、DNS 或账号配置。
- 先提交并推送私有子模块，再提交并推送主仓库的引用；不得引用尚未推送的私有提交。
- 隐私发布决定保留在公开的 `src/data/privacy-review.json`，详细依据放入私有资料。保持发布检查，不以迁移为由削弱审核。
- 工程检查与实际业务验收分别确认，不以网站检查替代其他验收。

## 八、SEO / GEO / AEO 与获客架构

本节依据用户 2026-10-04 的完整升级授权，扩展公开内容与流量入口；仍保留 Astro 静态站、GitHub Pages、英文默认、`/zh` 镜像和无运行时后台/跟踪原则。当前产品集合以 `catalog.ts` 为准，旧六产品枚举不再作为新增已授权产品的限制。

- Product 是事实与转化页；Guide 回答一个具体搜索问题；Template 提供免费可使用的记录表；主题 Hub 提供领域介绍、问题与流程，不只堆链接。不创建近义词重复页面、不保证排名或 AI 引用。
- `src/data/guides.json`、`templates.json` 为双语内容源，`resources.ts` 建立关联；共享 ResourcePage 和静态动态路由生成两种语言。新增已核实 App 时维护 listing、至少三篇独立 Guide 及适用模板，自动生成内链、Schema、Banner、sitemap 与 llms 发现入口。未有正式链接的产品不生成商店下载、Offer 或 Banner。
- Guide 第一屏给直接答案，英文约40–80词；包含清楚定义、对象、字段/清单、独立示例、步骤、错误、FAQ、来源与真实更新日期。流程建议明确为原创建议；引用外部事实时核对官方/原始来源。不把工作表字段都宣称为 App 功能。
- 免费模板无需账号、邮箱或跟踪。HTML可直接查看并用浏览器打印，英文PDF为静态可打印资源，中英CSV有UTF-8 BOM便于表格导入。`scripts/generate-templates.py` 从同一内容源生成资源，需要 authoring 环境 reportlab；生成后的文件提交到 `public/downloads/`，生产构建不依赖Python。内容/字段改变时必须重建，核对资产manifest哈希，逐PDF渲染检查字体、字段、裁切与打印布局。
- 产品、指南、模板互相链接；主导航保持 Products / Guides / Support / About，模板在资源入口与页脚可见。名称、收费、隐私、离线/云与公开链接依当前真实依据维护，网站验收不替代App验收。
- Organization 使用一致品牌、法律主体、正式域名与支持邮箱。首页加入WebSite；产品使用真实SoftwareApplication，只有已核实listing才含downloadUrl/Offer；Guide使用Article和真实发布日期/更新日；Template用准确WebPage；产品/指南/模板/主题入口使用BreadcrumbList。不编造Review、aggregateRating、用户数、资质、价格或客户。
- 一个内容一个主canonical。历史 `/storyundo`、`/cluemend`、`/affixhop`、`/carttinker`、`/beatmend`（含 `-support` / `-privacy`）及支持/隐私/中文短页保留可读，但canonical指向 `/products/<slug>` 对应页面，设置noindex,follow，退出sitemap；所有内部业务链接与语言切换使用主URL。Pages文件式路由保持无扩展名；`.html`已有同内容canonical，尾斜杠URL若404不自动当作另一索引页面。
- Sitemap包括所有可索引语言URL且每项唯一。`publishedAt`/`updatedAt`与`freshness.ts`是显式内容日期，不能在每次build写当前日期。只有主要内容、Schema或实质链接变更才更新lastmod；同步检查Product、Guide、Template、JSON-LD、llms和sitemap。
- robots明确允许Googlebot（Google搜索）、Bingbot（Bing搜索）、OAI-SearchBot（ChatGPT搜索）、ChatGPT-User（用户触发访问），保留wildcard Allow。GPTBot用于模型训练，与搜索crawler不同；当前授权未要求阻止，wildcard继续允许。不写虚构crawler、不加crawl-delay。
- `/llms.txt`只包含已公开产品事实、索引、正式商店与资源链接，禁止私有信息/凭据/内部状态；它是额外发现层，不是Google排名必需文件。不增加所谓AI/GEO专用排名meta；FAQ为内容，不强求FAQPage富结果。普通Product/Guide/Template不适用Google Indexing API。
- `app-store.ts`统一生成Campaign与Smart Banner。真实Provider Token缺失时仅输出普通商店URL，不生成假pt/ct；取得Apple生成的真实pt后从search-config或构建变量启用。Campaign最多30字符，过长时稳定截断加hash，保持来源差异。公开provider/verification标识不是账号凭据；不得在配置中存私钥、密码或认证token。
- IndexNow用公开合法key及根路径txt，构建manifest对主内容/SEO元数据/Schema建立指纹。部署前保留旧manifest，成功部署并核对live key/live manifest后提交新增或实质变化URL；首次接入可提交全站，未变更部署不批量提交。网络/服务失败保留receipt并有界重试，不撤回网站；配置错误必须修复。IndexNow接收不代表索引，也不能替代Search Console。失败重试使用保留的部署前baseline，避免已更新在线manifest遮蔽未成功提交的URL。
- `npm run seo:check`作为本地硬Gate：合法XML、准确lastmod、canonical/noindex/alias策略、完整唯一URL、双向hreflang/x-default、可解析且诚实的Schema、真实Banner/CTA、静态HTML、内链、资源哈希与来源新鲜度。Playwright保留Chromium/WebKit桌面/移动全部原有检查，新增资源下载MIME、无JS阅读/下载与语言切换；每页与320/768px布局继续完整覆盖。
- Lighthouse作为可留档报告，不因运行环境噪声直接阻塞Pages；目标Performance≥90、Accessibility/Best Practices/SEO≥95。实际查看代表性桌面/移动/中文页面与PDF，不将自动PASS或截图清单视为全图人工验收。
- 首阶段监控来自Google Search Console、Bing Webmaster/AI Performance与App Store Connect Analytics/Campaigns。保留无Analytics、Pixel、Cookie tracking或第三方运行时请求。账号验证/索引/真实归因未读取时标注EXTERNAL ACTION REQUIRED，具体步骤见SEO_EXTERNAL_ACTIONS，不推断Indexed或AI citations。
